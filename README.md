# literouter

**一个基于 C++23 与 mcpp 构建的本地 AI 中转站聚合器（API Relay Aggregator）。** 在本地起一个 OpenAI 兼容端点，把请求按你的配置自动分发到多个中转站，支持模型重命名、有序故障转移、熔断、SSE 流式透传以及遥测统计。

你只需将各类客户端（Chatbox、NextChat、Cursor、沉浸式翻译、Shell 脚本等）指向 `http://127.0.0.1:8787/v1`，剩下的交给 literouter——哪个中转站能提供对应模型、哪个挂了、哪个被限流了，全由它在毫秒级自动接管调度。

```text
┌──────────┐        ┌────────────────────────────┐        ┌─────────────────┐
│ 客户端    │  ───▶  │  literouter :8787          │  ───▶  │ 中转站 A (优先)  │
│ (任意     │  ◀───  │                            │  ◀───  │                 │
│  OpenAI  │        │  模型映射 · 优先级 · 熔断保护 │        ├─────────────────┤
│  客户端)  │        │  流式透传 · 自动重试 · 遥测  │  ───▶  │ 中转站 B (备用)  │
└──────────┘        └────────────────────────────┘  ◀───  └─────────────────┘
```

## 核心特性

- ⚡ **单端点聚合**：对外暴露标准的 `http://127.0.0.1:8787/v1`，统一管理多个中转站的 Base URL 与 API Key。
- 🛡️ **响应头闸门与流式无损故障转移**：首包响应头到达前触发故障（网络断开、超时、429、5xx）无缝切换下一个中转站；首包下发后即锁定连接，杜绝流式回答内容拼合串扰。
- 🔌 **熔断与探针自动恢复**：连续失败自动将中转站标记为熔断冷却，冷却期后以单请求作为探针自动验证恢复，避免无效请求拖垮响应。
- 🔐 **密钥零泄露占位符**：配置中支持 `${OPENAI_API_KEY}` 或 `${VAR:-fallback}` 环境变量引用，仅在网络请求发出瞬间内存解析，保存配置时完整保留原始占位符。
- 🌐 **原生双语支持**：内置完整中英多语言体系，支持根据操作系统语言自动匹配（Auto），提供界面与顶栏一键切换。
- 🔍 **动态界面缩放**：支持 80% 至 150% 缩放调节与快捷键缩放，搭配全自适应双列/单列流式响应式排版。
- 📊 **端到端遥测观测**：实时记录请求数、成功率、活跃在途量、平均延迟、Token 用量与流量吞吐，内置可追溯环形日志缓冲区。

## 快速开始

### 1. 编译构建
本项目基于现代 C++ 构建工具链 [mcpp](https://github.com/mcpp-community/mcpp)，一键编译所有组件：

```bash
mcpp build --workspace
```

### 2. 初始化配置与体检
```bash
# 生成默认配置文件模板
mcpp run -p cli -- config init

# 注入环境变量（示例配置中默认引用）
export OPENAI_API_KEY=sk-...

# 运行 doctor 体检：验证配置语法、环境变量展开与中转站连通性
mcpp run -p cli -- doctor
```

### 3. 启动代理服务
```bash
# 方式 A：前台运行 CLI 代理
mcpp run -p cli -- serve

# 方式 B：启动带硬件加速的桌面控制台（GUI）
mcpp run -p gui
```

### 4. 发起调用验证
```bash
curl http://127.0.0.1:8787/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d "{"model":"gpt-4o","messages":[{"role":"user","content":"Hello!"}]}"
```

或者将任何第三方客户端直接指向本地代理：
- **Base URL / API 基础端点**：`http://127.0.0.1:8787/v1`
- **API Key**：若未在 `server.api_key` 中设置校验密钥，填任意字符均可。

## 配置文件指南

默认配置文件保存在 `~/.config/literouter/config.json`（遵循 XDG 规范）。支持通过环境变量 `LITEROUTER_CONFIG` 或 CLI 选项 `--config <path>` 显式指定路径。

```jsonc
{
  "schema": 1,

  "server": {
    "host": "127.0.0.1",          // 监听地址（绑定至公网非回环地址若未设 api_key 将触发安全告警）
    "port": 8787,                 // 监听端口，设置为 0 表示由操作系统随机分配空闲端口
    "api_key": "",                // 客户端鉴权密钥；留空表示不验证 Bearer Token
    "pass_through_unknown": true, // 路由表未显式收录的模型，自动按优先级透传至声明了该模型的中转站
    "max_attempts": 0,            // 单次请求最大尝试中转站数量；0 表示遍历所有可用候选
    "circuit_failure_threshold": 3, // 连续失败几次触发中转站熔断
    "circuit_cooldown_sec": 30,     // 熔断后冷却时长（秒）
    "skip_open_circuits": true,   // 路由调度时是否优先跳过熔断中的中转站
    "log_capacity": 400,          // 内存环形日志最大缓冲条数
    "log_bodies": false,          // 是否记录请求体与响应体报文（默认关闭以保护提示词隐私）
    "log_body_limit": 2048        // 报文体截断保存的最大字节数
  },

  "providers": [
    {
      "id": "openai",                          // 唯一标识符，路由定义与统计均以此为键
      "name": "OpenAI 官方",                   // 控制台友好的显示名
      "base_url": "https://api.openai.com/v1", // 上游根地址（保留子路径）
      "api_key": "${OPENAI_API_KEY}",          // 支持直接填写明文，或使用环境变量占位符
      "enabled": true,                         // 是否启用该中转站
      "priority": 10,                          // 优先级，数值越小越优先尝试
      "weight": 1,                             // 同优先级下的权重（权重高者排在前面）
      "timeout_sec": 120,                      // 响应超时时间（秒）
      "connect_timeout_sec": 15,               // TCP/TLS 连接超时（秒）
      "supports_stream": true,                 // 是否支持流式传输（SSE）
      "models": ["gpt-4o", "text-embedding-3-small"],
      "headers": { "HTTP-Referer": "https://example.com" }, // 附加向上游发送的自定义 Header
      "chat_path": "/chat/completions",        // 自定义聊天补全端点路径
      "embeddings_path": "/embeddings",        // 自定义向量嵌入端点路径
      "note": "主站节点"
    }
  ],

  "routes": [
    {
      "model": "gpt-4o",             // 客户端请求的目标逻辑模型名
      "enabled": true,
      "targets": [                   // 有序候选链路：第 0 项优先，后续为故障转移兜底
        { "provider": "openai", "model": "gpt-4o-2024-08-06" }, // 允许重命名映射到上游物理模型
        { "provider": "relay-backup" } // 省略 model 字段表示保持逻辑模型名透传
      ]
    }
  ]
}
```

### 密钥安全引用

`api_key` 字段支持 5 种声明语法，均在**实际发起上游网络调用的瞬间**动态展开：

| 语法格式 | 说明 | 示例 |
|---|---|---|
| `"${VAR_NAME}"` | 从环境变量读取，未设置时视为空字符串 | `"${OPENAI_API_KEY}"` |
| `"${VAR:-fallback}"` | 从环境变量读取，若未设置则退回到预设值 | `"${RELAY_KEY:-sk-fallback}"` |
| `"$VAR_NAME"` | 简写环境变量语法 | `"$MY_API_KEY"` |
| `"sk-..."` | 明文静态密钥（本地保存时文件权限会被重置为 `0600`） | `"sk-123456789"` |
| `""` | 留空，适用于无需 Bearer 鉴权的局域网模型网关 | `""` |

> [!IMPORTANT]
> **绝对不可逆原则**：ConfigStore 在执行配置保存（`save()` / `saveAs()`）时，会强制保留原始环境变量占位符，严禁将内存中解析后的明文写回磁盘。

### 规则校验机制

CLI 的 `config validate`、`doctor` 以及 GUI 编辑窗口内置统一的规则引擎：

- 🔴 **Error 严重错误**：中转站 ID 重复、Base URL 不是合法的 HTTP/HTTPS 协议、路由引用了不存在的中转站、多条路由使用相同的模型名、端口越界等。
- 🟡 **Warning 警告**：引用的环境变量在当前系统环境中不存在、路由指向已禁用的中转站、监听在非回环地址且未配置客户端 API Key 等。
- 🔵 **Info 提示**：中转站未声明任何模型（只能通过路由显式指定）、端口设置为 0（动态随机）。

## 路由与故障转移原理

### 候选链生成算法

当客户端请求到达时，`Router::candidatesFor()` 按照以下顺序严格决定上游候选列表：

1. **显式路由匹配**：若请求模型在 `routes` 表中已注册且处于 `enabled` 状态，则严格按照该路由定义的 `targets` 顺序组装链路。这是**人工设定的权威顺序**，系统不会随意扰乱。
2. **全局自动透传**：若无路由匹配且 `pass_through_unknown = true`，系统将扫描所有已启用并声称拥有该模型的中转站，按 `priority` 升序排列（数值小的在前），同优先级按 `weight` 降序排列。
3. **未匹配处理**：若以上两阶段均无可用候选，立即向客户端返回标准 OpenAI 格式的 `404 model_not_found` 错误。

### 重试判定与“响应头闸门”

一次尝试失败后，是否切换至下一个候选站点的决策逻辑如下：

| 请求阶段与返回结果 | 是否触发故障转移？ | 行为解释 |
|---|:---:|---|
| 网络连接拒绝 / TLS 握手失败 / 超时 | ✅ 是 | 上游未承载或未开始处理请求，安全重试 |
| HTTP `408`, `409`, `425`, `429` | ✅ 是 | 速率受限或临时冲突，自动降级至备用站 |
| HTTP `500` ~ `599` 服务端故障 | ✅ 是 | 上游网关或模型服务崩溃，立即故障转移 |
| HTTP `400`, `401`, `403`, `404`, `422` | ❌ 否 | 属于客户端业务层错误，原样透传给客户端 |
| 流式（SSE）请求**首字节/响应头已发送给客户端** | ❌ 否 | **闸门关闭**：流已定案，杜绝拼装两个回答流 |

> [!CAUTION]
> **响应头闸门 (Header Gate)** 是 literouter 保障流式调用绝对一致性的核心基石。流式请求在专有读取线程上向上游建立连接，主响应管道等待首个数据块到达。在首包到达客户端之前发生任何异常均可无损切换；一旦响应头已送达客户端，生命周期即锁定，绝不拼接多次回复。

### 熔断器工作机制

当中转站遭遇传输错误或可重试状态码（如连续 5xx 或 429）达 `circuit_failure_threshold` 次后，熔断器进入 **Open（打开）** 状态，并在 `circuit_cooldown_sec` 秒内保持冷却：
- 冷却期间，该中转站会被降级移动至候选链的最末尾（若所有站点全部熔断，依然会尝试距离失败时间最久的一个）；
- 冷却期满后转入 **Degraded（降级恢复中）** 状态，下一个请求将作为试探流量；如果请求成功则立即恢复为 **Healthy（正常）**，若再次失败则重新进入熔断冷却。
- **纯粹性判定**：客户端取消连接（`aborted`）以及业务层语法错误（`400`）**绝不计入熔断失败计数**，确保健康站点不会因客户端的主动断开或传参错误被误杀。

## HTTP 接口定义

### 客户端兼容端点

| 方法 | 端点路径 | 说明 |
|---|---|---|
| `POST` | `/v1/chat/completions` | 主对话补全接口，完全支持 `stream: true` 的 SSE 流式透传 |
| `POST` | `/chat/completions` | 兼容省去 `/v1` 前缀的轻量级客户端 |
| `POST` | `/v1/completions` | 旧版文本补全兼容端点 |
| `POST` | `/v1/embeddings` | 向量嵌入生成接口 |
| `GET` | `/v1/models` | 列出当前聚合器支持的所有逻辑模型，带有 `literouter` 扩展路由拓扑说明 |
| `GET` | `/v1/models/{id}` | 查询指定模型的详细信息与候选状态 |
| `GET` | `/health` | 无需鉴权的存活健康检查探针（返回 `{"status":"ok"}`） |

### 内部管理端点

管理接口统一以 `/__literouter` 为前缀，供 CLI 与 GUI 交互使用（配置了 `server.api_key` 时同样需携带 Bearer Token）：

| 方法 | 端点路径 | 作用 |
|---|---|---|
| `GET` | `/__literouter/status` | 获取系统完整快照（运行状态、连接数、中转站健康度与统计数据） |
| `GET` | `/__literouter/logs` | 获取增量日志：支持 `since=N` 增量拉取与 `limit=M` 条数限制 |
| `POST` | `/__literouter/reload` | 通知代理热重载磁盘配置文件并无缝更新路由表 |
| `POST` | `/__literouter/reset-stats` | 重置所有遥测计数器与熔断器状态 |
| `POST` | `/__literouter/shutdown` | 安全优雅关闭后台代理服务 |
| `POST` | `/__literouter/probe` | 针对传入的中转站配置发起一次即时连通性探测（支持拉取模型列表） |

### 五大核心面板

1. **概览 (Overview)**：全局指标磁贴（请求量、成功率、延迟、流量）、中转站实时健康矩阵、熔断告警浮条与实时流量活动流。
2. **中转站 (Providers)**：中转站可视列表，支持一键开关、优先级与权重调节、探测测试，以及**自动探测上游模型并一键同步到配置**。
3. **路由 (Routes)**：以可视化流程节点展示每个逻辑模型的候选链，支持拖拽/点击调序、跳步故障转移链路实时直观预览。
4. **日志 (Logs)**：虚拟列表支撑的高性能请求记录查看器，支持按日志级别（全部/信息/警告/错误）、业务类别筛选，支持暂停、全文搜索与详情查看。
5. **设置 (Settings)**：服务端监听、熔断阈值、日志缓冲区、语言与缩放控制，内置一键保存、重载与即拷即用的接入 curl 示例。

### 多语言切换 (i18n)

- **语言选项**：支持 `English`、`简体中文` 以及 `跟随系统 (Auto)`；
- **快速切换**：在顶栏右侧点击 `[中/EN]` 按钮即可完成瞬时全局语言切换，所有组件标题、表单标签与状态均无缝本地化；
- **环境变量控制**：可通过 `LITEROUTER_LANG=zh` 或 `LITEROUTER_LANG=en` 锁定初始启动语言。

### 界面自由缩放 (UI Scale)

为了适配不同分辨率的显示器（4K、2K、笔记本小屏），GUI 内置了完整的 UI 矢量缩放引擎：
- **缩放档位**：支持 `80%`、`90%`、`100%`、`110%`、`125%`、`150%`；
- **便捷操作**：顶栏内置 `[-] 100% [+]` 控制步进，或进入设置面板点击预设档位；
- **全局快捷键**：
  - `Ctrl` + `+`（或小键盘 `+`）：放大界面
  - `Ctrl` + `-`（或小键盘 `-`）：缩小界面
  - `Ctrl` + `0`（或小键盘 `0`）：重置为 100% 原始大小
- **环境变量**：可通过 `LITEROUTER_UI_SCALE=1.25` 显式指定启动缩放系数。

### 高清中文字体自适应

针对 Linux 桌面常见的中文缺失或模糊问题，literouter 启动时会智能扫描系统已安装的清晰字形，按如下优先级加载：
1. **更纱黑体** (`sarasa-regular-nerd-font.ttc`)：基于思源黑体与 Iosevka 打磨，屏幕清晰度极高；
2. **文泉驿正黑** (`wqy-zenhei.ttc`)：经典 Linux 简体中文字形；
3. **Noto Sans CJK** 系列；
4. Windows 微软雅黑 (`msyh.ttc`) / macOS 苹方 (`PingFang.ttc`)。
亦可通过 `LITEROUTER_GUI_FONT=/path/to/font.ttf` 指定自定义字体。

        └── components/         # 声明式 UI 控件、主题配色与通用布局

### 架构设计准则

1. **纯接口隔离（Strict Contract Layer）**：`core/src/literouter_core.cppm` 是唯一对外公开的 C++23 模块。上游通信所使用的 `httplib::*` 和 `nlohmann::json` 被完全封装在 `.cpp` 实现内部，外部成员编译期不发生任何依赖泄漏。
2. **决策与网络严格解耦**：`Router` 是纯逻辑状态机，入参为模型名与历史结果，输出为候选站点列表，不持有任何网络套接字（Socket）。这使得复杂重试与熔断算法可以进行 100% 确定性的离线单元测试。
3. **线程热连接池（Thread-Local Connection Pool）**：为杜绝高并发转发时每个请求重复进行 TLS 握手导致的巨大延迟开销，内部采用无锁线程局部池（`thread_local ConnectionPool`）为每个中转站保留活跃长连接，实现零锁争用的极致性能。

## 已知边界

- **协议专注**：目前专注做好 OpenAI `/v1` 协议生态，不做跨厂商协议翻译（如 Anthropic 原生协议翻译为 OpenAI 协议）。
- **确定性调度**：同一优先级内部依据权重与声明顺序提供可复现的确定性回溯，不采用不可复现的随机分发。
- **内存日志环**：日志默认保存在内存环形缓冲区中，进程退出后清空；如需持久化留存，可对接标准输出日志收集工具。
